# 开发规范

## 基本原则

- 新代码使用 Kotlin。只有平台或第三方接口明确要求时才引入 Java。
- 一个文件只承担一个清晰职责；不要把业务继续堆回 `FileManagerView`。
- UI、文件系统、持久化和媒体播放通过明确边界通信。
- 先复用已有控制器和结果类型，再考虑新增平行实现。
- 请不要按特点设备的固定分辨率写条件分支。

## 我开发的功能应该放在哪里

| 修改内容 | 目录 |
| --- | --- |
| 文件列表、Dock、菜单绘制 | `ui/render/` |
| 菜单动作与显示条件 | `ui/menu/` |
| 动画、惯性、手势阈值 | `ui/motion/` |
| 选择、多选、滑选 | `ui/selection/` |
| 主题、字号、间距 | `ui/appearance/` |
| 标签和目录历史 | `navigation/` |
| 文件创建、复制、删除、撤回 | `operation/` |
| 鼠标与快捷键 | `input/` |
| 图片、视频、音频、文本查看 | `viewer/` |
| Android 资源 | `res/` |

如果某个修改需要在三个以上模块重复判断同一状态，应先增加模型或控制器接口，不要复制条件。

## UI 与响应式布局

- 使用当前 View 可用尺寸、系统 Insets、字体测量和内容约束计算布局。
- 尺寸使用 `dp`，文字使用 `sp`；像素只用于解码目标尺寸等明确的像素语义。
- 网格列数、行高和文本宽度必须从容器尺寸推导。
- 所有文字必须限制绘制区域，窄窗口下使用裁剪、缩略或滚动，不能溢出地址栏或弹窗。
- 状态栏、导航栏、刘海和 DeX 任务栏统一通过 Insets 适配。
- 浮动按钮图标通过几何中心计算，请不要使用依赖字体基线的特殊字符。

## 动画与手势

- 点击选择即时反馈，不要为普通文件点击增加无意义动画。
- 菜单动画从触发点展开，并在关闭时回到同一触发点。
- 动画由 `ui/motion` 管理，业务控制器不得自行维护动画进度。
- 长按和双击使用 Android `ViewConfiguration` 的系统超时。
- 拖拽距离使用 `scaledTouchSlop`。
- 设备兼容性去重、动画时长和防抖间隔必须使用有语义的常量，禁止在业务分支散落裸毫秒值。
- 多选模式下单击只切换一次选择；双击等于两次切换，不允许打开文件。
- 长按成功后必须提供震动或明确的视觉反馈，让用户知道可以松手或开始拖动。

## 文案与i18n

- 用户可见文字统一放在 `res/values/strings.xml`。
- 代码中不得拼接“重命名失败”“复制成功”等中文业务文案，请统一放置到文件目录下。
- 资源名称描述业务语义，例如 `action_delete_selected`，不要继续使用已改变含义的特殊命名表示标签。
- 带数量和动态内容的文字使用格式化资源。
- `contentDescription` 同样必须使用字符串资源。

## 文件操作

- UI 层不得直接调用 `File.renameTo`、递归删除或自行复制流。
- 底层异常在 `FileOperationService` 转为 `FileResult`/`FileProblem`。
- 大文件复制、移动、删除和撤回不得在主线程执行。
- 文件事务使用 `FileActionController` 的单线程队列，避免并发覆盖和回收站竞争。
- 执行器必须有明确生命周期：关闭后拒绝新任务，不强制中断正在进行的文件事务，并屏蔽失效 UI 回调。
- 新增可逆操作时同步定义 `PendingUndo`；不可逆操作必须在设计说明中写明原因。
- 更新 UI、选择和撤回栈必须发生在事务成功之后。

## 状态与持久化

- 标签状态通过 `DockSessionController` 修改，禁止直接在 UI 中改写标签集合。
- 持久化格式只由 `DockSessionStore` 负责。
- 新增持久化字段时必须兼容旧数据缺失、路径不存在和索引越界。
- 选择和撤回属于会话状态，除非产品要求改变，否则不写入磁盘。
- Activity 或 View 销毁时必须清理 Handler、动画、媒体播放器和后台执行器。

## 查看器与编辑器

- 媒体文件列表由 `MediaFolderPlaylist` 生成，不在每个 Activity 重复扫描逻辑。
- 图片缩放焦点必须保持在双指中心；缩放状态下不触发图片切换。
- 视频和音频切换后释放旧播放器，保存必要的恢复位置。
- 文本加载和保存保留原编码及 BOM。
- 高亮计算放到后台线程，只处理可见区域附近，并通过 revision/token 丢弃过期结果。
- Tab 插入四个空格；多行选择支持统一缩进和 Shift+Tab 反缩进。

## 桌面与键盘

- 新快捷键集中添加到 `DesktopShortcutResolver`。
- 快捷键触发的行为与触屏菜单复用同一控制器方法。
- 输入框和文本编辑器优先消费文字编辑按键，避免全局快捷键抢占。
- 为了避免某些特殊平板的键位映射（说的就是你小米💢），`Esc` 不应当作为映射为应用动作。
- 鼠标右键需要同时验证 Android 原生鼠标事件和 DeX 及类 DeX 的事件情况。

## 修改流程

1. 确定需求属于哪个模块，以及是否改变现有状态模型。
2. 搜索已有实现和字符串资源，避免重复控制器或重复文案。
3. 先修改模型/控制器，再修改绘制和命中逻辑。
4. 涉及持久化时验证升级安装与强制停止恢复。
5. 执行 `gradle :app:assembleDebug`。
6. 测试时候可以在模拟器完成交互回归，再在至少一台真机检查 Insets、字体缩放和触控。
7. 架构或规范改变时应同步更新 `docs/`。

## 提交前的检查

- 是否出现新的硬编码用户文案？
- 是否出现无名称的时间阈值或固定屏幕坐标？
- 是否在主线程执行文件或媒体重任务？
- 是否存在未关闭的 Handler、Animator、MediaPlayer 或 Executor？
- 窄窗口、横竖屏、字体缩放和系统 Insets 是否正常？
- 菜单是否只显示当前有效操作？
- 删除、移动、粘贴和撤回是否覆盖成功与失败路径？
